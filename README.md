# SSD-xApp for srsRAN + Open5GS + Mocked RIC Adapter

This project is a **software-only Signaling Storm Detection xApp (SSD-xApp)** based on the uploaded papers, adapted to a **zero-license-cost** lab stack:

- **srsRAN**
- **Open5GS**
- **Mocked Near-RT RIC adapter**
- **FastAPI**
- **PostgreSQL**
- **Redis**
- **Prometheus/Grafana-ready metrics endpoint**

It does **not** require a real E2 interface to get started. Instead, it uses a mocked adapter that mimics a Near-RT RIC event feed and policy callback path.

## What this project does

- builds a KPI profile per **TA** and **time bucket**
- computes anomaly scores
- raises alarms
- applies a policy ladder: `alert -> rate_limit -> reject`
- supports:
  - synthetic traffic generation
  - CSV replay
  - mocked live feed via Redis pub/sub
- includes an adapter contract so you can later replace the mocked RIC with:
  - srsRAN instrumentation
  - a custom gNB-side parser
  - or a true E2/RIC feed

## Quick start

### Option A — Local Python

```bash
unzip ssd_xapp_srsran_open5gs_mocked.zip
cd ssd_xapp_srsran_open5gs_mocked
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload
```

Then open:

```text
http://127.0.0.1:8000/docs
```

### Option B — Docker Compose

```bash
unzip ssd_xapp_srsran_open5gs_mocked.zip
cd ssd_xapp_srsran_open5gs_mocked
docker compose up --build
```

App endpoints:

- API: `http://127.0.0.1:8000/docs`
- Metrics: `http://127.0.0.1:8000/metrics`

## Minimal flow

### 1) Train KPI profile from synthetic clean traffic

```bash
curl -X POST http://127.0.0.1:8000/train/synthetic \
  -H "Content-Type: application/json" \
  -d '{
    "preset": "testbed_clean",
    "cell_id": "cell_1",
    "windows": 60,
    "window_sec": 60,
    "base_ta": 77
  }'
```

### 2) Run inference with mixed traffic

```bash
curl -X POST http://127.0.0.1:8000/infer/synthetic \
  -H "Content-Type: application/json" \
  -d '{
    "preset": "testbed_mixed",
    "cell_id": "cell_1",
    "windows": 30,
    "window_sec": 60,
    "base_ta": 77
  }'
```

### 3) Inspect alarms and policies

```bash
curl http://127.0.0.1:8000/alarms
curl http://127.0.0.1:8000/policies
curl http://127.0.0.1:8000/profiles/cell_1/77
curl http://127.0.0.1:8000/config
```

## Mocked RIC live feed

Start the app, then run a mock publisher:

```bash
python scripts/mock_ric_publisher.py --preset testbed_mixed --cell cell_1 --base-ta 77
```

Start live consumption:

```bash
curl -X POST http://127.0.0.1:8000/live/start
```

Policies generated by the xApp are published back to Redis channel:

```text
ric:policy
```

You can watch them with:

```bash
python scripts/policy_listener.py
```

## How this maps to srsRAN + Open5GS

This repo gives you the **xApp core** and a **mocked RIC path**. To integrate with your software lab later, replace the mocked event producer with one of these:

1. a parser that tails and converts gNB / core logs into `RAR-like` events with `TA`
2. a custom hook in your lab that publishes event JSON to Redis topic `ric:events`
3. a future adapter that speaks to a real RIC/E2 source

The xApp expects event JSON like:

```json
{
  "timestamp": "2026-04-07T15:00:00Z",
  "cell_id": "cell_1",
  "event_type": "RAR",
  "ta": 77,
  "ue_temp_id": "0x1234",
  "request_type": "connection_establish",
  "result": "observed"
}
```

## Recommended next step

Use this repo first exactly as-is. Once stable, connect your **srsRAN/Open5GS experiment** by writing a small converter that emits the same event schema to `ric:events`.
